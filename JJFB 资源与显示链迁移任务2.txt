十、修复决策树
完成 pointer provenance 后，必须在同一任务中实施对应修复，不要停在“已定位”。
Case 1：R9 / generation 错误
现象：
C0 entry R9 不是当前 Robotol R9
或 root object 来自旧 generation
修复：
deferred family event 保存 owner module_id/generation
top-level flush 前执行 module_r9_switch
callback frame 绑定 generation
generation 不匹配则拒绝执行并重新调度正确 owner
不得硬写 root pointer。

Case 2：平台 query/out 没写出 nested object
现象：
Guest constructor 调用了平台 API
API ret=MR_SUCCESS
但 out pointer 保持 0
修复该真实 API：
按已证明 ABI 分配 Guest object
写出 guest *out
初始化必要通用字段
注册 ownership
不得根据：
PC=0x2FEC3C
触发。

Case 3：对象已分配但 constructor 被跳过
现象：
root allocation 成功
constructor 入口未到达
或平台 callback 提前 return
修复：
缺失的 callback 返回 ABI
缺失的 lifecycle scheduling
缺失的 constructor platform dependency
让 Guest 自然执行 constructor。
不得由 host 直接填整张结构体。

Case 4：对象字段是显示/runtime descriptor
只有动态证明 LDRSH 读取的是：
screen width
screen height
x/y geometry
pitch
时，才允许迁移旧版 descriptor 语义。
正式新增：
include/gwy_launcher/platform_runtime_descriptor.h
src/platform/platform_runtime_descriptor.c
通过 profile/Launcher 初始化：
screen_width  = 240
screen_height = 320
pixel_format  = RGB565
绑定：
module_id
module_generation
Guest descriptor object
不得复制旧：
FAST_F74_DESCRIPTOR_ASSIST
那种直接写固定 ER_RW offset 的方式。

Case 5：nested pointer/child object 未分配
修复真实 child-object allocator/constructor。
要求：
Guest address
正确 allocation size
正确 alignment
零初始化规则
generation ownership
对应 free
不得使用固定地址 0x6BBBB8 或任意 scratch object。

Case 6：对象 stale / use-after-free
修复：
owner reference
queue/callback lifetime
generation invalidation
destructor timing
不得简单禁止 free。
