Task 14：正式发布 Robotol DrawFP，解开 2FC26C，并闭环 E6C 生产链
一、任务目标
当前已证明：
record-first
→ downVersion compare
→ B71 natural store
→ POST_DRAIN_GATE_OK
→ family C0
→ 0x30DC44
→ 0x2FEBBC
→ 0x2FEC3C 因 ER_RW+E6C == 0 失败
empty-first 实验已证明：
empty Path-A
→ 0x2FC26C entered
→ 卡在 0x2FDD5C 附近 DSM/cfunction 循环
→ 0x2FC3E6 leave 未到达
→ event 15 未出现
→ ER_RW+E6C 仍为 0
旧 V67 已知同类根因：
ER_RW+0x150C 的 drawFP 为 0 / 0x270F / CODE_ADDRESS / 非法 Guest 地址
→ 进入绘图 wrapper 后 BLX 到坏地址
→ Guest execution 停在 2FC26C 中途
→ 事件 drain 无法返回
本任务目标不是复制旧版“跳过 BLX”补丁，而是：
正式发布 _DrawBitmap 平台 callback
→ ER_RW+0x150C 获得有效 Guest-callable trampoline
→ 2FC26C 内绘图调用可以正常返回
→ 自然到达 0x2FC3E6
→ 继续嵌套 1E201 / event dispatch
→ 验证 event 15 是否自然产生
→ 验证 0x2E4020 → 0x2E5E60 是否自然写 ER_RW+E6C

旧版关键事实：
1. DrawFP 字段
Robotol 使用：
ER_RW + 0x150C
作为 _DrawBitmap 平台函数指针。
实际调用 wrapper：
0x2EC6B8
...
0x2EC714：从 ER_RW+0x150C 加载函数指针
0x2EC71A：BLX drawFP
旧版识别为坏指针的值：
0
0x270F
< 0x1000
CODE_ADDRESS
未映射 Guest 地址
2. 旧 V67 的临时做法
旧版在坏指针时：
恢复 0x2EC6B8 的栈
设置 R0=1
PC=LR
从而绕过 BLX，让 2FC26C 能继续返回。
这个做法只能作为 A/B 证明，不能进入正式产品。
3. _DrawBitmap 的两种 ABI
Classic ABI
R0 = pixels
R1 = dst_x
R2 = dst_y
R3 = copy_width

SP+0x00 = copy_height
SP+0x04 = rop
SP+0x08 = transparent/key
SP+0x0C = source_x
SP+0x10 = source_y
SP+0x14 = source_pitch/image_width
Robotol wrapper ABI
识别特征：
(SP+0x00 & 0xFFFF) == (R3 & 0xFFFF)
且值非 0
参数语义：
R0 = pixels
R1 = dst_x
R2 = dst_y
R3 = source_pitch/image_width

SP+0x00 = copy_width
SP+0x04 = copy_height
SP+0x08 = rop
SP+0x0C = flags
SP+0x10 = source_x
SP+0x14 = transparent/key
source_y = 0
本轮主要会遇到 Robotol wrapper ABI。

五、实现 Guest-callable _DrawBitmap callback
新增正式 host callback，例如：
uint32_t platform_guest_draw_bitmap(void *uc);
流程：
读取 R0-R3
读取 SP+0x00..0x14
判断 classic / Robotol wrapper ABI
校验 Guest pixels
校验宽、高、pitch
执行安全 RGB565 blit
设置 dirty rect
按平台 ABI 返回
通过原 LR 返回 Guest
安全要求
必须校验：
guest_pixels != 0
copy_w > 0
copy_h > 0
src_pitch > 0
copy_w <= src_pitch
copy_w/copy_h 不超过合理范围
Guest pixel range 已映射
所有乘加无 32 位溢出
目标裁剪在 240×320 内
遇到非法对象或当前尚未有可用 pixels 时：
不得 UC_FAULT
不得跳入 cfunction/DSM
不得 host 造像素
不得构造假 bitmap
应安全返回失败/未绘制状态。
返回值先按旧 V67 已证明可继续的：
R0 = 1
同时跟踪 0x2EC71A 返回后的 Guest 指令是否读取 R0：
若 R0 未使用，保留 1；
若明确用于条件判断，按实际平台语义调整；
不可凭猜测改成 MR_SUCCESS=0。

六、RGB565 绘制语义
Robotol wrapper 使用：
src_pitch = R3
copy_w    = SP+0
copy_h    = SP+4
src_x     = SP+0x10
src_y     = 0
key       = SP+0x14
实现：
for (int y = clip_y0; y < clip_y1; ++y) {
    int sy = args->src_y + (y - args->dst_y);

    const uint16_t *src =
        guest_pixels
        + sy * args->src_pitch
        + args->src_x
        + (clip_x0 - args->dst_x);

    uint16_t *dst =
        framebuffer
        + y * screen_width
        + clip_x0;

    for (int x = clip_x0; x < clip_x1; ++x) {
        uint16_t pixel = *src++;

        if (args->transparent_enabled &&
            pixel == args->transparent_key) {
            dst++;
            continue;
        }

        *dst++ = pixel;
    }
}
透明色：
0xF81F 为明确有效 RGB565 key
小于 0x100 的值默认视为 flag/rop，不直接当透明色
本轮即使还没有有效 bitmap pixels，也要确保 callback 正常返回，使 2FC26C 不再被坏 FP 截断。

七、正式发布 drawFP，而不是运行时 PC hook
1. 找到现有 mr_table 发布链
复用当前已经发布以下平台能力的同一机制：
memcpy import
mr_table
extChunk
platform callbacks
定位：
ext_chunk_provider
ext_module_data_init
ext_er_rw_producer
gwy_ext_obs_extchunk_set_mr_table
mr_table builder / callback registry
2. 注册 _DrawBitmap
旧平台 table offset：
_DrawBitmap = mr_table + 0x1E0
不得把 C host 地址直接写进 Guest。
必须通过现有 Guest-callable host callback/trampoline 注册机制得到：
draw_bitmap_trampoline_guest
然后在构建正式 mr_table 时：
*(mr_table_guest + 0x1E0) = draw_bitmap_trampoline_guest
3. 发布到 Robotol ER_RW+0x150C
Robotol 初始化或平台表绑定完成后：
*(robotol_er_rw + 0x150C) =
    *(mr_table_guest + 0x1E0)
要求：
按 module identity
按 module generation
按当前 Robotol ER_RW
不得根据：
PC == 0x2EC6B8
PC == 0x2EC71A
PC == 0x2FDD5C
临时写入。
不得使用旧：
jjfb_heal_shadow_gfx
的运行中 fixed-offset heal 模式。
正确位置应是：
mr_table 创建/发布
或 Robotol platform table 初始化
